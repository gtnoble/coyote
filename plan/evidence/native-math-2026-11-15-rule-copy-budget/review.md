# Read-only review — parser array-rule copies

**Scope.** Reviewed the working-tree diff for `src/coyote_math/math_syntax.adb`, `src/coyote_math/math_syntax.ads`, and `test/tools/math_parser_memory_probe.adb`; checked surrounding parse/reservation code and local GNAT 13.3 vector runtime sources. No source edits or tests were run. Retained ownership/API migration is not approved by this review.

## Findings

### 1. Blocking: the outer-growth accounting scan itself makes nested rule-vector copies

At `math_syntax.adb:246` and again at `:274`, `for Existing of State.Item.Nodes loop` iterates an Ada.Containers vector whose `Iterator_Element` is `Node` (`math_syntax.ads:158-159`; GNAT `a-convec.ads:95-96`). GNAT's element operation returns `Element_Type` by value (`a-convec.adb:613-624`). Therefore each loop element is a copied `Node`; because `Node.Array_Rules` is a controlled vector, copying that field invokes vector `Adjust`. GNAT vector `Adjust` allocates and copies the active elements (`a-convec.adb:134-164`), not merely a reference to the node. These temporary rule-vector copies are then finalized per iteration. The first scan is intended to estimate copies caused by outer `Nodes.Reserve_Capacity`; the second scan is intended to reconcile resulting capacity. Both scans can themselves allocate nested buffers, and those buffers are not charged. Repeated scans also add transient work/allocation at each outer growth.

This means the new estimate is incomplete and can understate peak memory at exactly the operation it purports to account for. It is not fixed by saying the outer vector `Adjust` copies active rule elements: the accounting loop introduces separate, real temporary nested copies. The same hazard applies to any by-value iteration over `Node` containing controlled vectors in this code.

**Bounded correction:** iterate node cursors and inspect via `Constant_Reference`/`Constant_Reference_Type` (or another documented non-copying reference/query API), not `for Existing of`. Avoid retaining a reference across `Reserve_Capacity` or any node-vector mutation. Verify both scans compile without a value copy. If reference iteration is awkward, provide a private helper that queries each node's rule length/capacity by cursor while the node vector is stable. Then account only allocations actually performed by GNAT `Reserve_Capacity`: active Array_Rule elements copied to the replacement nested vector for the first phase, and actual old/new capacities for capacity-resident bytes as appropriate. Keep allocator overhead explicitly excluded.

### 2. The operation being charged is plausible for this GNAT, but qualification is implementation-specific

Local GNAT 13.3 `a-convec.adb:134-164` shows vector `Adjust` reconstructing storage over `Index_Type'First .. Last`, i.e. active length. `Reserve_Capacity` allocates the new backing array and assigns `Src` over active indices (`:2816-2834`); it allocates before freeing old storage (`:2842-2858`). Thus the rule-copy temporary for `Nodes.Reserve_Capacity` is the sum of each active `Array_Rules.Length * Rule_Width`, while the outer node backing overlap is old plus new backing capacity. This supports the intended model for the installed GNAT implementation. Ada container contracts do not guarantee GNAT's exact internal allocation/copy strategy or allocator byte use; the API documentation describes capacity behavior, not a portable allocator/RSS accounting model. The spec's assertion “Copy admission follows GNAT vector Adjust semantics” is appropriately explicit, but it must not be generalized to portable memory accounting.

The active-length term is conceptually distinct from nested vector spare capacity: GNAT `Adjust` recreates copies at length, while the old original vectors and their spare capacity remain live until the outer copy finishes. The subsequent capacity reconciliation is intended to restore normal-live capacity charges. This accounting distinction is sound only after eliminating the by-value scan copies in finding 1.

### 3. Probe's purported independent detector is not a reliable allocation-boundary oracle

The new code at `math_parser_memory_probe.adb:175-193` infers the outer-copy event from any poll where the observed account increase is at least `64 * Node_Record_Width`. The test uses a separate rule-free parse to establish `Node_Overlap_Delta` (`:779-800`), then expects the rule fixture delta minus that fixed amount to equal one rule width (`:802-830`). This is not an independent detector of the rule copy itself: it observes the same implementation-owned budget ledger, uses the first qualifying delta rather than an explicit growth event, and depends on a hard-coded growth-size interpretation. `Node_Overlap_Delta` is printed but not compared; the actual assertion subtracts `Outer_Node_Copy_Bytes`, not the control's observed delta. The label “independent rule copy bytes” overstates what the assertion proves.

The inserted `Math_Work_Control.Poll` at `math_syntax.adb:265` also changes when the probe can observe/stop. In particular, it is after the two pre-admissions but before `Nodes.Reserve_Capacity`; the tests can therefore demonstrate charge visibility at that new boundary, not independently prove which component caused each byte or that the scan itself didn't allocate. The baseline comparison includes the test additions and recognizes the lack of this specific poll, so differing baseline behavior is expected; it is not evidence by itself that the final detector is independent.

**Bounded correction:** introduce a narrowly scoped test seam/event for “immediately before outer `Nodes.Reserve_Capacity`” with explicit observed old capacity, requested new capacity, active array-rule lengths, and expected arithmetic derived from the fixture (or restructure a local helper so the test can verify the computed estimate without global sampling). Keep budget-ledger integration as a separate assertion: seed a budget, inspect reservation bytes at that explicit event, and separately test exact/one-byte-short behavior. Avoid asserting byte decomposition from generic poll deltas. At minimum, assert the rule-free measured control delta is used as the baseline and document why its growth transition matches the fixture; add negative controls where another charge changes but rule counts do not.

### 4. Cancellation and deadline assertions overlap exactly; they do not test different failure paths

The cancellation and deadline cases at `math_parser_memory_probe.adb:878-941` set identical thresholds/fixture/stop point and differ only in `Reason` and expected exception. The callbacks return at the same `Stop_On_Outer_Overlap` branch, and `Parse` catches both through the same `when others` restore/re-raise path (`math_syntax.adb:3634-3637`). These cases provide useful checks that each exception identity propagates and releases reservations, but are duplicate coverage of the same cleanup point, not independent evidence for cancellation-vs-deadline behavior. Shared-scope variants repeat the same pairing (`:943-1017`).

**Bounded correction:** retain one parameterized overlap cleanup case for each exception identity if both public exception contracts matter, but report as one shared cleanup branch with two identities. If distinct path coverage is desired, use a real monotonic deadline mechanism for the deadline case or place the two stops at deliberately different phases (e.g. after node reservation vs before it) and assert which reservations have been acquired/released. Avoid describing them as independent overlap coverage.

### 5. Retained rule-field preservation is only partially covered

The outer-growth assertion (`math_parser_memory_probe.adb:833-855`) checks one array, one rule, `Kind = Solid_Array_Rule`, and `Boundary = 1`. Those are all fields of `Math_Model.Array_Rule` (`math_model.ads:38-42`), but it does not exercise preservation of `Dashed_Array_Rule`, multiple rules/boundaries, or rule ordering across outer-node growth. Other pre-existing checks exercise multiple rule kinds / boundaries for other fixture paths (e.g. the probe's later post-array assertion), but those do not establish that a nested vector containing those values survives the specific outer `Nodes.Reserve_Capacity` copy.

**Bounded correction:** change this growth fixture to contain at least one solid and one dashed rule at distinct boundaries before forcing outer node capacity growth; inspect the returned array node and assert both ordered `(Boundary, Kind)` pairs. Keep the current single-rule minimal case if useful, but don't characterize it as complete retained-field coverage.

### 6. Arithmetic, pre-admission ordering, and exception/finalization paths

- `math_syntax.adb:237-238` guards `(Old_Capacity + New_Capacity) * Width` by checking `New_Capacity <= Natural'Last / Width - Old_Capacity`; given parser capacities are `Natural` and bounded, the sum/product is protected. The rule-overlap summation at `:247-255` checks remaining `Natural` room before multiplication/addition. The capacity sum at `:275-283` has the analogous guard. The later rule-capacity correction at `:2601-2602` is safe if the earlier reservation invariant holds: pre-admission includes the old capacity plus requested new capacity, and `Actual_Capacity` is the post-call replacement capacity. Still, encapsulating checked add/multiply helpers would reduce reliance on this invariant and improve auditability.
- Both copy charges are reserved before the outer allocation: rule overlap first (`:257-258`), node old/new backing next (`:262-264`), then poll (`:265`), then `Reserve_Capacity` (`:266-267`). This is proper pre-admission order for the intended allocation. The later post-growth rule-capacity reconciliation (`:274-286`) is post-allocation by nature; if it rejects after actual allocation, exception cleanup frees local state, but a budget limit is not a strict pre-admission guarantee for capacity that GNAT over-allocates beyond the request. Current code only asks `Reserve_Capacity` for the requested capacity and then reconciles actual capacity; document this limitation if the allocator/runtime may return more.
- `Node_Reservation` and `Rule_Reservation` are declared before `State` in `Parse` (`:3454-3461`), so `State` finalizes first on normal return/exception; reservation owners release after parser locals are gone. The comment at `:3458` is correct. Result nodes are moved out by `Take_Result` (`:3471-3484`) and therefore are no longer call-local storage; they remain uncharged after Parse returns, as the spec expressly says. This is the separate retained-ownership hazard already identified in project instructions; this review does not approve changing that API/ownership model.
- The newly added pre-Reserve poll can throw after both reservations have been acquired but before `Reserve_Capacity`; reservation finalization releases both, and the outer Parse handler restores macro scope (`:3634-3637`). `Parse_Failure` cleanup and normal local/global group restoration also remain ordered as before. The new arithmetic exceptions and budget exceptions follow the same finalization path. The outer local `Rule_Overlap` block finalizes before the subsequent node pre-admission and has no persistent accounting ownership; its reservation is the owner itself, not that block-local scalar.

## 719-check evidence and scope

The retained `test-worker/final-5-console.log` reports 719 checks and zero failures, but the current `final-console.log` in the same evidence directory reports one failure for the “independent rule copy bytes” assertion; previous run logs vary in the number of failures. The accepted subdirectory has a zero-failure run. This review does not rerun or adjudicate those historical runs. A check count is not proof of independence, and a passing assertion based on the above shared ledger/poll observation does not close the missing-test-oracle issue. The 719 checks include the prior probe body plus the new cases; they are not 719 new independent claims.

The parser change plausibly closes the *intended GNAT active-rule-copy admission gap* only after the copy-producing iteration is removed and the tests are corrected. It is not whole-job memory accounting, allocator/RSS accounting, a guarantee for returned documents, qualification, or acceptance. Retained ownership migration remains unapproved and is outside this change.

## Recommended bounded disposition

1. Replace both by-value node iterations in the growth path with cursor/reference inspection and ensure no temporary `Node`/`Array_Rules` copy is made by the accounting logic.
2. Replace poll-delta decomposition with an explicit pre-allocation observation seam or direct checked-helper test; keep budget exact-fit/short tests separate.
3. Make the outer-growth preservation fixture cover both rule kinds, multiple distinct boundaries, and ordering.
4. Describe paired cancellation/deadline cases as shared cleanup-path coverage (or separate their actual stop phases).
5. Preserve the existing `Parse` reservation lifetime and returned-document ownership model pending user review; do not imply that this scoped fix resolves the retained-budget proposal.
